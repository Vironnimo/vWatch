# Glossary

Shared vWatch terms that can be confused with the coding agent's own environment. Mechanisms and payloads belong to the named domain map.

## Project

A watched repository with a stable vWatch identity, owner intent and retained interpretation (application). It is not the coding agent's current checkout; moving its folder does not create another Project.

## Facts

Read-only measurements of a repository and its locally visible Git state, with optional CI evidence (repository-facts). They are not an agent's assessment or proof of a remote backup.

## Card

The agent-authored interpretation and re-entry material for one Project (application). Its current version can be outdated even while Facts are fresh.

## Portfolio brief

The cross-project interpretation that helps the owner choose focus and consider patterns or proposals (application). It does not replace individual Cards or measured Facts.

## Due

A reason the interpretation needs review against current evidence or owner instructions (application). It is not an instruction to modify the watched repository.

## Context Token

An opaque guard tying a document write to the context the agent read (persistence). It is not an authentication credential or a durable permission to overwrite later work.

## Run

A recorded vWatch observation cycle covering project review and portfolio synthesis (application). It is not the shell process or the coding agent's chat.

## Task

A retained assignment made by the owner, including its source and subsequent reports (application). An agent's completion report asks for owner review; it does not itself confirm completion.

## Job

A recoverable CLI operation continuing beyond the console's wait budget (agent-interface). It is not a Task assigned to a coding agent or a daily Run.

## Proposal

A retained suggestion from project or portfolio interpretation, classified as an idea or a recommendation (application). A rating expresses taste; it does not assign implementation.

## Own idea

An idea recorded by the owner for later agent assessment (application). It is distinct from an agent-authored Proposal even when both appear in the ideas collection.

## Feedback

The owner's rating, reply, note or completion decision attached to a stable item (application). It is instruction to the interpreting agent, not disposable report content.

## Read acknowledgement

The owner's explicit acceptance of the displayed report snapshot as read (application). A visit, reload or Facts refresh does not acknowledge anything.

## Undo

A guarded reversal of a saved vWatch change that must preserve intervening work (persistence). It is not permission to reset the whole database or replay a mutation blindly.

## Operating Skill

The instructions vWatch exports for external agents using the installed CLI (agent-interface). It is separate from this repository's Vorch development rules.
